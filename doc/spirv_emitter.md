# SPIR-V Emitter

## Abstract
The emitter converts a GPU Machine IR kernel into a deterministic SPIR-V 1.3 binary module plus a kernel manifest, with no external compiler dependency. The module verifier rejects invalid output before any driver sees it.

## Formal Definitions
```rust
pub struct SpirvModule { words: Vec<u32>, id_bound: u32, entry_point: String }
pub struct KernelManifest { entry_point: String, bindings: Vec<KernelBinding>, workgroup: WorkgroupDims, push_constant_size: u32, required_features: Vec<String> }
```

## Algorithm
The verifier checks one terminator per block, branch targets, declared bindings, and SSA single definition. Emission allocates ids in two deterministic passes (pre-scan for constants, then per-instruction values and labels) and serializes sections in grammar order: header, capabilities, memory model, entry point, execution mode, names, decorations, types, constants, globals, function.

## Invariants
1. Ids are defined before use and exactly once; the bound covers every allocated id.
2. The word stream is byte-identical across runs for the same kernel.
3. Every binding reference in an instruction is declared on the kernel.
4. The checked-in grammar table is generated from the official `spirv.core.grammar.json` and regenerated byte-for-byte by the repository script.

## Integration Points
* Depends on: nothing outside `std` and the checked-in grammar.
* Depended on by: the GPU runtime tier (device enumeration and pipeline creation are ticket CEP-210).

## Known Limitations
Module output is verified by this crate's verifier; cross-validation against spirv-val and driver-level execution are deferred with the GPU runtime ticket. Access-chain pointer typing for storage-buffer members uses derived ids rather than a full type table. Kernels with loops emit structured control flow but are not exercised end to end in this environment.
