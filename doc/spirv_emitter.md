# SPIR-V Emitter

## Abstract
The emitter converts a GPU Machine IR kernel into a deterministic SPIR-V 1.3 binary module plus a kernel manifest, with no external compiler dependency. The module verifier rejects invalid output before any driver sees it.

## Formal Definitions
```rust
pub struct SpirvModule { words: Vec<u32>, id_bound: u32, entry_point: String }
pub struct KernelManifest { entry_point: String, bindings: Vec<KernelBinding>, workgroup: WorkgroupDims, push_constant_size: u32, required_features: Vec<String> }
```

## Algorithm
The kernel verifier checks one terminator per block, branch targets, declared bindings, SSA single definition, and undefined uses. Emission allocates every result id from one counter in a deterministic pre-pass (types, binding chains, constants including the barrier scope and semantics constants, per-instruction values, access-chain results for loads and stores, labels, function), aliases in-kernel constant and local-id values to their global ids, and serializes sections in grammar order: header, capabilities, memory model, entry point, execution mode, names, decorations, types, constants, globals, function. Access chains carry the struct member index zero plus the element index against a dedicated element pointer type. Conditional branches emit OpSelectionMerge naming the false target as the merge block. Workgroup barriers emit OpControlBarrier with workgroup scope and WorkgroupMemory semantics ids. The word verifier then re-parses the emitted stream and rejects any result id at or above the bound, any duplicate definition, and any used id that is never defined.

## Invariants
1. Ids are defined exactly once and every used id is defined somewhere in the module; the bound covers every allocated id.
2. The word stream is byte-identical across runs for the same kernel.
3. Every binding reference in an instruction is declared on the kernel.
4. The checked-in grammar table is generated from the official `spirv.core.grammar.json` and regenerated byte-for-byte by the repository script.

## Integration Points
* Depends on: nothing outside `std` and the checked-in grammar.
* Depended on by: the GPU runtime tier (device enumeration and pipeline creation are ticket CEP-210).

## Known Limitations
Module output is verified by this crate's two-stage verifier; cross-validation against spirv-val and driver-level execution are deferred with the GPU runtime ticket. Selection merges name the false target, which is correct for if-without-else shapes; genuine diamonds and loops need a merge-block construct in GMIR and remain unexercised (ticket CEP-210). Local invocation ids alias the zero constant rather than reading the LocalInvocationId builtin.
